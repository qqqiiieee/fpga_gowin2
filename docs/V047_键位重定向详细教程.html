1．改的是哪一层

编辑项索引 / 槽的含义填入的数字不随它改变的内容
notes[128]索引是旋律通道输入的原始 MIDI 音符；例如 Note 60。该键交给发声器的目标音高。默认 notes[i]=i。物理按住高亮、逐音找键基准、光电扫弦选和弦仍用原始音高。
pads[4]槽0→Kick；1→Snare；2→Closed Hat；3→Open Hat。通道10（内部编号9）上触发对应鼓声的来源音符。鼓声动作固定；不会把Pad变成旋律琴键，也不改发送通道。
cc[4]槽0→Delay；1→Chorus；2→Reverb；3→Volume。控制固定功能的来源CC编号。旋钮硬件发出的编号、软接管规则、保护CC的原作用。

单射就是不能重复。Note表有128项，每项为0..127整数且互不重复，因此它是0..127的一次完整置换。改60→62时必须把原来占用62的目标移走，例如同时改62→60。只覆写一项会被网页/ESP校验拒绝。底层接口的兼容说明不等于手机允许多键合并。

音符编号0是合法音高，不是“静音”。映射表允许0..127；屏幕可见键域及自定义曲谱范围是41..72（F2–C5），初次操作请在这个范围内交换。旋律按当前默认接收通道1；Pad按通道10，不能只看编号相同就认为可互换。

2．先保存能回退的基线

  1. 连接：两板正常供电时，手机连接热点 Tang20K-Music，密码 fpga2026，打开 192.168.4.1，再进入 /extensions。本地热点没有互联网，选择继续连接。
  2. 确认链路：等待 FPGA 已连接及有效实际回读。网页能打开只证明 ESP32 可访问。当前已拔ESP时，只阅读和准备文件，不能做手机硬件验收。
  3. 整理演奏状态：退出振荡器验证，暂停曲谱，选 KEY 输入模式，松开全部琴键与踏板，停止扫光电；录音需停止并排空。先演奏60、62各一次，记住原声音和松键结果。
  4. 读取并备份：在“运行时 Note / 四Pad / 四CC映射”点击“读取已保存 / 当前映射”，记下是否本次已确认生效。再点“导出映射 JSON”，自行保存为便于识别的备份名。导出的是编辑框内容，先读取才能避免备份未提交草稿。
  5. 确定演示起点：若已有自定义映射，备份后先按第8节提交FPGA默认映射。这样后面的60/62示例有明确起点；不需要恢复默认时，必须检查所有占用关系。

应看到：链路有效、没有录音作业、默认音能正常松开、备份已下载。任一项不符先排查，不用重新烧录来代替状态确认。

3．案例A：把60与62真正交换

步骤操作与效果验证 / 恢复
① 准备编辑框在默认基线上点“编辑框恢复默认”。此时128项为原值，Pad为[36,38,37,39]，CC为[93,91,71,74]。提示“尚未提交”；FPGA没有因为这个按钮改变。
② 同时改两项展开“编辑128个旋律 Note”，将 Note 60填62，Note 62填60，其余126项保持原值。手动编辑会将草稿标记为启用自定义映射。此时只修改草稿。不要改完第一项就提交；那时62重复、60缺失。
③ 提交确认所有键和踏板已松开，点击“提交完整映射并保存”。确需主动停音时，先勾选“提交前发送并等待 FPGA Panic 确认”。等待作业完成；“已入队”不算成功。若报忙，按第8节恢复空闲后重试。
④ 再读取点击“读取已保存 / 当前映射”。应显示“FPGA本次连接已确认自定义映射生效”，并仍为60→62、62→60；它是ESP对本次提交的确认，不是逐项扫描FPGA RAM。
⑤ 单键检查新按原始60：声音应为62；新按原始62：声音应为60；原始64仍为64。每次松开并等待尾音。屏幕按住高亮仍在原始键位。长Release或FX尾音不等于卡音，先关FX、缩短尾音作比较。
⑥ 独立松键检查同时按60和62，先松60再松62；换一次松键顺序。先松60应释放其映射音62，仍按住的62所发60继续保持；反向同理。不要用踏板干扰这次验证。
⑦ 恢复松键并点“提交 FPGA 默认映射”，等完成后重新读取。应显示已禁用自定义映射；60、62恢复原音。若要恢复原自定义配置，导入第2节备份并重新提交。

5．案例B：交换两个Pad的鼓声动作

数组槽网页标签默认来源禁用自定义后恢复的全部别名
pads[0]Kick 来源3635、36
pads[1]Snare 来源3838、40
pads[2]Closed Hat 来源3737、42
pads[3]Open Hat 来源3939、46
  1. 先确认控制器实际发送通道10，且Pad音符确实是36、38、37、39。物理Pad排列可能不同；按钮位置不能代替来源消息确认。
  2. 在完整映射中将Kick来源改38、Snare来源改36，Closed Hat保留37、Open Hat保留39，即 pads:[38,36,37,39]。四项各为0..127且互不重复。
  3. 松键、停演奏，按第3节提交与读取。敲原始36应为Snare，原始38应为Kick；另两Pad保持原鼓声。四个来源逐个敲一遍，保留声音证据。
  4. 恢复时用备份重新提交，或提交FPGA默认映射。恢复后35/36均可Kick、38/40均可Snare，镲声别名也恢复。

启用自定义时，仅配置的四个来源有效。即使只改了Note，Pad旧别名35、40、42、46也可能不再触发。Pad无声先查通道、来源和启用状态，不要去改notes[36]补救。

6．案例C：旋钮换功能与软接管

槽顺序（不可按数值排序）默认来源固定目标
cc[0]93Delay 强度
cc[1]91Chorus 强度
cc[2]71Reverb 强度
cc[3]74Volume 总音量

四项为互不重复的0..127整数，禁止使用保护CC：1 / 7 / 64 / 120 / 121 / 123。即使底层仍能识别某些原动作，手机入口也不会允许占用；例如不能拿CC7填Volume槽来绕过限制。

  1. 换来源：确认控制器K1发93、K3发71。把Delay来源改71、Reverb来源改93，保留Chorus=91、Volume=74，即 cc:[71,91,93,74]。效果为K1控制Reverb、K3控制Delay。
  2. 提交并确认：执行空闲提交、再读取。此时旋钮仍发送原CC，FPGA把来源转给对应固定功能；改映射不会改键盘固件。
  3. 完成软接管：缓慢转到该功能保存值附近或扫过该值，再继续转一点，使数值真正变化。各效果独立保存强度，非当前效果不是追着当前Wet走。
  4. 比较声音：K1接管并变化后应选择Reverb，弹短音听残响；K3接管并变化后应选择Delay，弹短音听重复回声。K2验证Chorus起伏，K4验证总音量实际回读。
  5. 重新接管：手机切FX或改强度、改音量后，相关旋钮可能需再次扫过新的目标；按实际回读判断。恢复默认或导入原备份后，再检查各旋钮功能。

仅匹配目标值只取得接管资格，继续变化才选择效果；反复发送相同值不会抢占模式。MIDI是0..127，页面部分实际量是0..255，不能机械对比数字相等。三个FX共用引擎，一次启用一种；强度0为干声。换来源后，未被分配的旧旋钮CC不会继续作为该旋钮功能生效。

保留60↔62映射，先用原始音高60的单音目标做检查：

操作应观察到的结果含义
KEY模式按下原始60物理按住高亮仍对应60；声音是62。高亮监视输入原始音符，音频使用映射结果。

8．提交、Panic、禁用与恢复的准确区别

动作实际效果如何收尾
读取、导入、编辑、导出读取保存/已知值或修改本地草稿；不自动提交。需要应用时另点提交；要放弃草稿则重新读取。
编辑框恢复默认只加载默认草稿，标记disabled=true。要改变FPGA，仍需提交；后续手动编辑任一数值会重新标记启用。
提交完整映射并保存发送完整表到暂存区域，最终提交被接受后原子生效，然后保存ESP文件。等最终作业结果，再读取本次确认；不能只拍进度或请求ACK。
勾选提交前Panic先明确请求并等待停音确认，再提交/禁用。会清持续音并停止导奏，涉及原有程序/弯音/调制等复位语义。提交后检查音色与控制值，松开后重新按键；需要继续曲谱时重新开始。
未勾选Panic不是无缝热切换。仍要求演奏空闲和MIDI安全边界；接受映射提交本身也清理旧音与输入状态。松开琴键和踏板、停止光电及自动演奏，等待尾音与忙状态消退后提交。
提交 FPGA 默认映射执行MAP_DISABLE，禁用自定义表，恢复恒等旋律、默认CC及全部Pad GM别名；成功后保存默认状态。重新读取确认，再试60、62和各Pad。它不是只给128项填回原值。

三个可照做的恢复场景

  1. 报“FPGA忙”：停止录音并排空、暂停导奏、退出测试、松开键与踏板、停止旋钮/扫弦输入。等待后重试；需要强制停音再勾Panic。Panic也不能绕过录音占用或断链。
  2. 超时 / Panic未确认：不要把新表当作已生效。确认链路，读取状态；若仍不确定，空闲时重新提交目标完整表或默认映射，直到有最终确认，再实弹。断链期间不能保证自己看到的旧状态仍有效。
  3. “FPGA映射已生效，但Flash保存失败”：这时不能笼统说“什么也没改”。先导出要保留的完整配置，处理存储问题后重提并确认；需要原行为则提交默认。不要格式化存储来当作恢复映射按钮。

9．保存、重启与断电边界

位置 / 场景保留什么回来后做什么
手机编辑框未提交草稿不等于ESP保存；刷新页面可能丢失。重要方案导出JSON到手机/电脑。
ESP32 LittleFS成功保存的映射含启用/禁用状态，正常断电后可读取；曲谱文件与最近一段录音也存这里。看保存结果，保留外部备份；不要在写入时断电。
FPGA复位 / 两板断电运行时映射复位为禁用；自定义曲谱RAM需重新上传/激活。ESP有文件不等于FPGA已应用。重新连接，读取已保存表，再提交并验证；曲谱也重新上传保存的JSON。
仅ESP重启 / 拔掉ESP若FPGA供电及复位未受影响，已有FPGA运行状态可继续；ESP重启读取保存文件，但不会据此确认或自动恢复FPGA映射。重新连接后的active_confirmed初始不是成功证明。读取、按需要重提并实弹，不能把失去确认直接当作映射已失效。
下载或重启后播放旧WAVV046允许HTTP读取已保存录音；重启后做文件结构检查，不是重新完成一次FPGA端到端CRC验证。展示当次录音通过时的结果；旧文件播放应标明回放。USB读取有当前启动会话限制。
LittleFS初始化会清空该分区的曲谱、映射和录音；不是恢复某一张表。仅按明确需要使用，先下载备份。已有重启问题在V046修复，不能把初始化当成常规步骤。

“已保存”“作业已入队”“FPGA本次已确认”是三个不同结论。重新读取的映射是ESP保存/已知配置；最终还要用实际按键和松键验证。

10．配合逐音验证的单音示例与V047和弦边界

无需升级即可给V046上传的单音示例

现成文件：上传验证_兼容V046单音.json，包含16个单音、8拍、100 BPM，使用score/1，无需升级到V047。下方三音序列另用于简短键位核对。

以下是自编三音检查序列，不引用版权曲谱。在曲谱区粘贴或导入（V046标题为“自定义单音曲谱”，V047开发页面为“自定义曲谱 · 最多四音和弦”），点击“保存并上传 FPGA”，等完成后选择自定义曲及所需模式，再开始。默认有两拍预备。上传曲是额外自定义槽，不替换三首预置曲；再次上传会更新这个自定义槽。

{
  "schema":"tang20k.score/1",
  "title":"键位核对三音",
  "bpm":100,
  "events":[
    {"pitch":60,"start":0,"duration":1,"velocity":90},
    {"pitch":62,"start":1,"duration":1,"velocity":90},
    {"pitch":64,"start":2,"duration":1,"velocity":90}
  ]
}

V046单音格式：1..63事件，音高41..72、力度1..127、BPM 30..240；start/duration以拍为单位，必须落在1/4拍网格。按起始时间排列，不重叠；旋律最多61拍，加固定两拍预备共不超过63拍。也支持整数start_quarter / duration_quarters，这里的quarter是一拍的四分之一；不要混用两套字段。JSON上限16384字节。

V047开发目标：1..4音同起止和弦

需配套新FPGA与ESP47，尚待最终发布验证。新原创曲已保存为霓虹阶梯_黑白键双音四音_V047.json：59组、144音、32拍、116 BPM，作为额外自定义曲，不替换预置三曲。V046旧单音页面不能用“把多个音填在相同start”方式冒充和弦；也不能宣称V047已烧录。以下为确定的V047格式约定，开发源码已加入解析，不是现有硬件成功记录。
  • 新schema为tang20k.score/2，events每组使用pitches:[...]，含1..4个41..72范围内升序、唯一音高。
  • 同组共享start / duration / velocity，共同起止；最多63组，按时间顺序排列，不同组不能重叠。不是63个音的总数，也不是可任意叠加的多轨文件。
  • 兼容旧tang20k.score/1单音。固定BPM与自动演奏计划支持和弦；固定BPM照常不等待、不替人发声，自动演奏按组发声。
  • 逐音和弦必须为当前目标新按过目标音，并且全部目标键同时保持才推进。依次点完并松开不算多键同时按；提前一直按住、只踩踏板延音不替代新按键。

11．易错点速查

现象原因 / 处理
只改60→62就报错62被用两次。默认起点应同时62→60；已有自定义表则先寻找目标的原占用者。
JSON里有交换，声音仍原样检查disabled是否为true、是否只导入未提交、是否已重启FPGA、实际输入是否为旋律通道、是否处在STRUM。
映射后屏幕仍亮原键原始输入显示的预期行为。不要把它当成提交失败。
目标音听起来正确但逐音不推进比较的是原始键，且要求新的正确按键；检查实际模式、是否处在演奏页及暂停状态。
改Note后某些Pad别名不响整表启用使Pad仅识别四个指定来源；提交默认映射恢复全部旧别名。
CC填写7或64报错保护CC禁止占用；四槽顺序是Delay、Chorus、Reverb、Volume，不能按CC大小排序。
旋钮刚动不变、手机调完又不跟随先扫过对应保存目标，再改变数值；查看实际回读，不用反复提交映射解决软接管。
点“编辑框恢复默认”后仍映射尚未提交。需要真正恢复则点“提交 FPGA 默认映射”，等待完成再读。
停音后重新按键才响Panic/提交清理了按住状态；先松开再按。Panic停止导奏后也需重新开始。
有文件却显示未确认存储与运行时状态不同；按第9节重连、重提并验证。
