# V015 → V034 更新说明与交接重点

说明日期：2026-10-31（北京时间）。本文比较的是 **GitHub 原有 V015 与本次准备发布的 V034 的最终状态**，不只列 V033 → V034 的增量，也不包含对话或中间版本归档。

对比基线为提交 [`c07e7d102666b751fb6ad2635397e008569a83a3`](https://github.com/qqqiiieee/fpga_gowin2/commit/c07e7d102666b751fb6ad2635397e008569a83a3)，旧版配置和资源取自该提交的 [manifest.json](https://github.com/qqqiiieee/fpga_gowin2/blob/c07e7d102666b751fb6ad2635397e008569a83a3/manifest.json)。新版行为以当前 [top.v](../src/top.v)、[引脚约束](../src/multi_tone.cst)、配套 ESP32 源码和 V034 编译、回归记录为依据。

**当前项目已经从“矩阵键盘＋双压力鼓＋双滑杆”转为“MIDI 主演奏＋双光束扫弦＋双 FSR 表情＋四键面板＋手机参数面板”。32 个独立相位与包络声部保留；普通音色由 16 种收敛为 2 种。**

> 发布状态：V034 的 FPGA 和 ESP32 均已编译，已记录的软件回归通过；本版尚未烧录。当前实物 FPGA 仍是 V033，ESP32 仍是此前已部署程序。旧版已经听到琴声、手机链路已经连通，不等于 V034 的混合演奏已通过实机验收。

## 1. 功能究竟增删了什么

| 部分 | GitHub 原有 V015 | 当前 V034 | 性质与注意点 |
| --- | --- | --- | --- |
| 演奏键盘 | 4×4 扫描矩阵；低 12 位演奏，高位复用控制 | 独立 MIDI 串口接收键盘，面板按键不产生音符 | 更换生产输入；旧矩阵模块保留兼容用途 |
| 普通音色 | 16 种 | 0：柔和长笛；1：拨弦 | 精简音色，不减少 32 个旋律声部 |
| 两片 FSR | 分别触发底鼓、军鼓 | FSR1 改明亮度；FSR2 改拨弦阻尼、制音 | 已取消生产中的“压力触鼓”映射 |

| 输入模式 | 单一矩阵演奏路径 | KEY／STRUM／HYBRID | HYBRID 允许键盘与扫弦叠加，共享原有 32 声部 |
| 四旋钮 | 无此映射 | Delay、Chorus、Reverb、总音量 | 三效果共用一个效果引擎，当前一次选一种效果 |
| 打击乐 | 底鼓、军鼓，由 FSR 触发 | MIDI Pad 触发底鼓、军鼓、闭镲、开镲 | FSR 不再承担鼓击输入 |
| 本地面板 | 矩阵高位键和组合键 | 4 路独立共地薄膜按键，增加长按切音色、切模式 | 松手确认，多键取消；PMOD3 分配见下文 |
| HDMI 指引 | 四页中文状态和跟弹提示 | 四页保留，增加真实黑白键、物理按键高亮和下落音符指引 | 显示窗为 F2–C5，不再把半音画成一排等宽白键 |
| 手机控制 | 无 | ESP32 Wi-Fi AP、浏览器参数页、真实状态回读、预设导入导出、Panic | 手机不合成音频；声音仍由 FPGA 输出 |
| 音频串行输出 | 板载 PT8211；外接 `amp_*` 固定为 0 | PT8211 保留；`amp_*` 增加 PCM5102A 标准 I2S | 两种串行格式不同，不能互换 DIN/WS 时序 |
| 32 频验证 | 有测试控制和现场入口 | 引擎仍保留，当前顶层缺少用户启动入口 | 属于交接待补项，不能按 V015 的矩阵快捷键直接演示 |

### 删除、停用与兼容代码要分开看

- **生产功能已经停用**：4×4 矩阵演奏、模拟电容键盘菜单、实体滑杆、FSR 触鼓，以及普通演奏的另外 14 种音色。
- **源码仍然保留**：`matrix_keypad.v`、`slider_controls.v`、`pressure_adaptive.v`、`mcp3208_reader.v`、`analog_touch_keypad.v`、旧菜单模块及原 16 音色波表。它们用于参数化兼容、生成资产或回归对照；文件存在、列入工程，不等于生产顶层正在实例化其功能。
- **当前生产选择**：`TOUCH_ENABLE=0`，`DISPLAY_TOUCH_ONLY=1`，`PRESSURE_EXPRESSION_ENABLE=1`，`PHASE_RAM=1`。`DISPLAY_TOUCH_ONLY` 是历史参数名，当前含义应按具体 generate 分支判断，不能理解成正在使用触摸屏。
- **仍未实现**：显示屏 USB 触控、FPGA USB-MIDI Host、HDMI 音频包。当前 MIDI 入口是外置 MIDI 接收模块送来的串行逻辑信号；HDMI 负责视频。
- `tests/fixtures/` 等目录中的 `v015`／`legacy`／`reference` 名称用于兼容、等价性回归，不代表本次发布包含多套可运行历史固件。实际生产顶层仍是工程文件指定的 `top`。

## 2. 当前操作与接口约定

### 四键面板

| 面板键 | FPGA PMOD3 引脚 | 短按后松开 | 长按约 0.8 秒后松开 |
| --- | --- | --- | --- |
| 1 | A11 | 切换页面 | 长笛 ↔ 拨弦 |
| 2 | B11 | 开始／暂停／继续引导 | KEY → STRUM → HYBRID → KEY |
| 3 | N6 | 重播当前曲 | 仍重播，只执行一次 |
| 4 | D11 | 下一曲，并等待开始 | 仍选下一曲，只执行一次 |

四路输入使用 3.3V 上拉、按下接公共 GND；这块常开薄膜按键不接 VCC。默认消抖 20ms。长按 1/2 不附带短按动作，多键或中途换键会取消本次手势。上电按住或测试模式退出后，需全松开才能重新接收。按住面板键会冻结教学时间轴，不暂停正常音频。

本板曾报告 PMOD1 异常，因此当前按键和手机 UART 均避开 PMOD1。不要沿用旧版的 T11/P11/T12/R11 面板接线。

### 键盘与扫弦

| 模式值 | 名称 | MIDI 琴键 | 光电输入 |
| --- | --- | --- | --- |
| 0 | KEY，上电默认 | 正常发出所选音色 | 不产生扫弦音符 |
| 1 | STRUM | 记录按住的音符，选择和弦，不直接发声 | 按方向依次弹出和弦，使用拨弦音色 |
| 2 | HYBRID | 正常发出所选音色 | 额外叠加所选和弦的拨弦音 |

扫弦事件以触发时的按键快照为准，最多取 6 个音；没有按住琴键时使用 C4/E4/G4/C5。A→B 为升序，B→A 为降序。上电前两束光均保持畅通，前端会学习空闲电平，不能把固定高低电平直接当成“有光／无光”。

HYBRID 没有新增一套 32 声部；MIDI 与光电共用原有槽位。同音可能叠加，满载遵循分配器现有抢占规则。切换模式会清理旧声音和效果尾音，切换后松开并重新按下琴键再演奏。

### 旋钮、打击垫与 FSR

| 控件 | 当前作用 | 维护或测试重点 |
| --- | --- | --- |
| K1／CC93 | Delay 强度 | 先跨过当前保存值，再继续旋转 |
| K2／CC91 | Chorus 强度 | 改变并接管后切到 Chorus |
| K3／CC71 | Reverb 强度 | 改变并接管后切到 Reverb |
| K4／CC74 | 总音量 | 跟踪实际音量目标，不把启动时旋钮位置立即写入 |
| 通道 10 Pad | 36 底鼓、37 闭镲、38 军鼓、39 开镲 | 同时兼容代码列出的 GM 别名；更改键盘 Pad Bank 后应重新观测实际 Note |
| FSR1／ADS1115 A0 | 连续改变明亮度 | 看校准状态与平滑后控制量；不是直接音量，也不是 kg 读数 |
| FSR2／ADS1115 A1 | 拨弦阻尼、制音 | 用拨弦音色测试音符尾音；对长笛不按同样方式生效 |

旋钮采用软接管，初转无变化可能是尚未到达目标值。三种效果各保存自己的强度，但不组成三效果串联链。效果强度为零时是干声。FSR 需在无压力状态启动并完成基线学习，断采样会重新校准；已经制掉的拨弦尾音不会因松开 FSR 自动重生。

部分兼容接口仍叫 `pressure_vibrato`，但生产路径在 [instrument_audio_top.v](../src/instrument_audio_top.v) 将第二路传给 `damping`；**当前第二片 FSR 的主要功能是阻尼，不应依旧变量名宣称为揉弦**。

### 手机与三条独立串口路径

| 路径 | FPGA 引脚 | 速率 | 用途 |
| --- | --- | --- | --- |
| 外置 MIDI 接收 | T8，`midi_rx` | 31250bps | 琴键、CC、Pad |
| FTDI 调试 | T13 RX、M11 TX | 115200bps | 电脑诊断、虚拟输入；与手机控制分开 |
| ESP32 手机控制 | L9 RX、N8 TX | 115200bps | ESP32 GPIO17 TX → L9；N8 → GPIO16 RX；共 GND |

手机通过 Wi-Fi 连接 ESP32，不需要手机数据线。三根 UART 线固定在作品内部；ESP32 和 FPGA 各自正常供电，两块板的 3V3 输出不相连。AP 为 `Tang20K-Music`，默认密码 `fpga2026`，浏览器地址为 `http://192.168.4.1/`。

**必须配套升级 FPGA 和 ESP32**：参数 2 的合法范围由 0/1 扩展为 0/1/2。旧桥接固件可能拒绝 HYBRID 的回读值，从而无法完成参数同步。网页显示提交成功只表示请求已排队；最终状态以 FPGA ACK 和后续 GET 为准。`/api/state` 中的 `linked`、`synced`、`stale` 用来区分连通、同步与旧值，不能只看上一次显示的参数。

**已知文案欠账**：本次 V034 源码的 [web_ui.h](../esp32_phone/web_ui.h) 帮助段仍有旧 T11/P11 接线文字，与当前 [CST](../src/multi_tone.cst) 和 [esp32_phone.ino](../esp32_phone/esp32_phone.ino) 的实际配置不符。当前应接 **L9/N8**。修正文案后需要重编译 ESP32、更新固件哈希，不能把新源码与旧二进制标成完全匹配。

## 3. 代码更新要点和阅读顺序

当前主链路为：输入解析与仲裁 → 带来源标签的声部分配 → 32 声部共享合成 → 打击乐混音 → 去直流／明亮度滤波 → 全局效果 → 音量 → 双音频串行输出。HDMI 和遥测从旁路读取状态，不拥有音频调度。

| 代码入口 | 相较 V015 的主要变化 | 修改时必须保留的契约 |
| --- | --- | --- |
| [top.v](../src/top.v) | 接入独立四键、手机协议、三态模式和下落指引；移除生产矩阵端口 | 模式只有一个真实寄存器；手机同周期绝对值优先于面板切换，回读必须来自生效状态 |
| [instrument_inputs.v](../src/instrument_inputs.v) | MIDI／光电汇合，压力表情，控制参数银行，无滑杆生产分支 | ADS A0/A1 与按键发声独立；缺少或故障 ADC 不应阻塞 MIDI 琴键 |
| [midi_keyboard.v](../src/midi_keyboard.v)、[midi_control_bank.v](../src/midi_control_bank.v) | MIDI 消息、held 状态、延音、CC、打击垫；旋钮软接管和手机参数仲裁 | 不吞 Note Off；物理 held、延音尾音、发声 busy 分开；请求值不是实际音量 |
| [performance_input_hub.v](../src/performance_input_hub.v) | 按 KEY／STRUM／HYBRID 仲裁事件；输出来源标签和诊断 | `valid && ready` 才消费事件；仅 STRUM 屏蔽琴键直接发声；模式变化取消旧演奏请求 |
| [optical_strum.v](../src/optical_strum.v)、[strum_player.v](../src/strum_player.v) | 双光束校准、方向／速度、和弦快照、逐音与对应释放 | 回压期间字段稳定；重触发先处理已接受音符的释放；不能只删挂起 Note On 而漏 Note Off |
| [voice_allocator.v](../src/voice_allocator.v)、[wavetable_synth.v](../src/wavetable_synth.v) | 来源隔离、两音色元数据、相位 RAM、实时 ADSR 和拨弦阻尼 | MIDI 与光电同音互不错误释放；32 独立相位／包络仍共享运算，不是 32 套并行完整合成器 |
| [instrument_audio.v](../src/instrument_audio.v)、[audio_effects.v](../src/audio_effects.v) | 四种打击音混音、可调明亮度、共用延迟存储的效果器、尾音管理 | 一帧 288 个主时钟；`sample_tick`／`frame_done` 是使能而非新时钟；尾音不能在松键时立刻截断 |
| [pressure_expression.v](../src/pressure_expression.v)、[ads1115_reader.v](../src/ads1115_reader.v) | 分通道基线、死区、平滑和过期恢复；生产只轮询压力通道 | 不以 A2/A3 更新冒充压力新样本；稳定按压不能被基线适应吞掉 |
| [pcm5102a_i2s.v](../src/pcm5102a_i2s.v)、[pt8211_driver.v](../src/pt8211_driver.v) | 新增标准 I2S，保留右对齐 PT8211，同一 PCM 分送 | I2S MSB 相对 LRCK 延迟一位；右声道 LSB 跨帧边界不能丢失；不可直接复制 PT8211 数据相位 |
| [piano_layout.vh](../src/piano_layout.vh)、[piano_roll_renderer.v](../src/piano_roll_renderer.v) | 共享 F2 起点、黑白键几何、对应下落轨道 | 显示范围 MIDI41–72，C4=60；改显示起点不要给声音或曲谱也整体移调 |
| [piano_roll_guide.v](../src/piano_roll_guide.v)、[piano_roll_score.v](../src/piano_roll_score.v) | 固定节拍时间轴与三首练习序列 | 默认 120BPM、两拍预备；时间轴不等按键、不自动发音，不是自动伴奏 |
| [hdmi_live_display.v](../src/hdmi_live_display.v)、[hdmi_status_cdc.v](../src/hdmi_status_cdc.v) | 紧凑界面、held 32 位图、谱面状态、HYBRID 标志整包跨域 | 生产状态包 339 位；兼容分支为 242/252/289/290/338 位；不逐位同步总线，不移动旧字段 |
| [phone_control_link.v](../src/phone_control_link.v)、[bridge_core.h](../esp32_phone/bridge_core.h) | 独立 UART 参数协议、ACK、范围校验、队列与过期同步 | 12 字节完整合法帧才提交；参数 2 最大 2；参数 15 只读；网页显示以真实回读为准 |

资源优化不是简单降低声部数：生产音色元数据从每声部 4 位缩为 1 位；波表使用 2×512 点半表恢复完整波形；相位改为同步 RAM，并用有效位屏蔽未初始化内容；界面字符采用生成的查找表；若干计数状态按实际范围定宽。原 16 音色波表仍作为生成和兼容回归基准，不能只因生产不用就随意删除。

界面文字、查找表和波表有生成源与校验脚本。修改 `assets/` 后应同步生成对应 `.vh`／`.hex` 并检查，避免只改生成产物、下次生成又被覆盖。

## 4. 资源与时序：相对 V015 的真实变化

下面是两个版本各自已记录的 Gowin 构建结果。它们比较的是完整最终工程，不能据此把某个单独功能的成本归因到某一行。

| 资源 | V015 | V034 | V034 − V015 | V034／器件容量 |
| --- | ---: | ---: | ---: | ---: |
| Logic | 14873 | 16940 | +2067 | 81.69%（20736） |
| Register | 6638 | 8100 | +1462 | 50.08%（16173） |
| CLS | 9357 | 9510 | +153 | 91.72%（10368） |
| BSRAM | 23 | 27 | +4 | 58.70%（46） |
| DSP | 11.5 | 15.75 | +4.25 | 65.63%（24） |

**精简和优化释放了部分资源，但加入新交互、效果器、手机链路和显示后，整机并没有比 V015 更小。当前最紧的是 CLS，剩余 858；不能只凭 Logic 剩余约 18% 就认为还有同等扩展空间。**

| 时钟域 | 实际要求 | V015 报告 Fmax | V034 报告 Fmax |
| --- | ---: | ---: | ---: |
| `clk27` | 27MHz | 32.469MHz | 30.303MHz |
| `pixel25_2` | 25.2MHz | 25.640MHz | 48.409MHz |
| `serial126` | 126MHz | 1238.658MHz | 858.728MHz |

两版记录均为 Setup 0、Hold 0。报告 Fmax 是时序估计，并非把实际时钟提升到该频率；V034 主时钟估计余量为 3.303MHz。新增组合逻辑、声部运算或像素流水后，必须重查布局布线报告，不能沿用旧 PASS。

主时钟仍为 27MHz，音频采样率仍为 93750Hz。新增模式和双输出没有改变音频帧预算。

## 6. 交接后优先处理什么

1. **先核对双固件身份并完成配套部署。** FPGA 目标为 V034／`0x000099D5`；ESP32 也必须接受三模式。FPGA 要做外部 Flash 写入、校验及重载，随后真正断电重启确认，不能把 SRAM 临时下载当成固化完成。此操作不是本说明编写阶段已经做过的工作。
2. **统一手机帮助接线文案。** 实际 GPIO17→L9、N8→GPIO16；网页中旧 T11/P11 要修正并配套重编译。验证 `linked=true`、`synced=true`、`stale=false`，再测试面板改变参数能否被手机读回、手机写入能否被 HDMI 显示。
3. **做三模式实物验收。** KEY 验证直接演奏、STRUM 验证琴键只选和弦、HYBRID 验证两路同音互不错误关断；测试延音、快速重扫、模式切换、Panic 和音量余量。应保存实测结果，不能只留“能出声”。
4. **补回可演示的 32 振荡器验证入口。** [top.v](../src/top.v) 当前明确 `ui_test_keys=16'd0`，生产 `DISPLAY_TOUCH_ONLY=1` 使旧矩阵／虚拟键不能直接成为测试控制键。引擎和状态页存在不等于用户能启动测试。后续增加正式面板或协议命令时，复用原 `test_owned`、淡入淡出、音频清理和正常输入交接机制，不用预混音频替代独立振荡器验证。
5. **解决 PCM5102A 无声的实物闭环。** 当前外接 BCK=B14、LRCK=A15、DIN=B13；板载耳机有声不证明这些线和模块工作正常。数字输出、接线、模块供电／配置和最终模拟可闻性应分别验证；万用表测到时钟平均电压不能证明格式和频率正确。
6. **验证 FSR 与光电实际量。** 压力先无载校准，再分别检查明亮度与拨弦制音；光电先看 raw／blocked／ready，确认有光和遮光确实变化，再测方向。原始量是控制码，不应标为 kg；固定输入电平不能当作已验证光束。
7. **每次扩展重新看 CLS、帧预算和来源释放。** 当前显示和控制功能已较多；优先保留实时音频、整包 CDC、Note Off、Panic 与效果尾音的契约，再考虑新增功能。源码存在兼容分支时，先查生产参数再删“冗余”。

## 7. 保留到下一位维护者的关键事实

- 真实键盘显示窗是 **F2–C5、MIDI41–72、19 白键＋13 黑键**。音频仍接受完整 MIDI 音符范围；黑白键的颜色不规定不同响度或音色。
- 当前教学为三首固定练习曲及视觉时间轴。它不等待正确按键后才前进，也不自动演奏伴奏；不应把该实现描述成任意 MIDI 曲库播放器或完整评分音游。
- 无滑杆、无电容键盘是有意的生产配置；ADS1115 为双 FSR 服务，MCP3208 接口保留但默认停用。
- 手机不在线时，本地面板、MIDI、扫弦仍可工作；FPGA 重启恢复 KEY 等默认状态，当前没有自动恢复掉电前整套参数的设计。
- `amp_*` 是兼容端口名，当前驱动的是 PCM5102A I2S，不代表本机正在使用 MAX98357 扬声器方案。
- 数字静音、去直流和滤波已存在，但不能据此承诺消除板外供电、地线、DAC 或耳机模拟链路的底噪。
- 当前不应声称“赛题所有要求已验收”。32 频启动入口、V034 双固件实机联调、真实扫弦以及外接 PCM 输出，应按上面的待办完成并补证据。

操作细节参见 [V034 面板与混合模式说明](V034_面板长按与键盘扫弦混合.html)、[ESP32 与效果器说明](ESP32接线与效果器使用.html) 和 [光电扫弦与无滑杆接线](光电扫弦测试与无滑杆接线.html)。接线冲突时始终以当前 [multi_tone.cst](../src/multi_tone.cst) 和实际使用的模块版本为准。
