3　V018 既有接法保留

接线基线来自本工程的 V018 触摸键盘接线与测试、V018 独立接线图和 当前引脚约束。本次只增加 MIDI / 光电线路；先逐项核对基线，再验证新增功能。

触摸 / MCP3208 · PMOD0

  • GVS：V → 3.3V，G → 公共 GND。S → 10k → MCP CH0；同一 CH0 节点再经 10k → GND。
  • MCP 模块 3V3 → 3.3V，G → GND；5V–18V 端子悬空。S 不直接接 FPGA 数字脚。
  • CLK ← T6；DIN ← P6；OUT → R8；CS ← T7。箭头以实际信号流为准。
  • 单路模拟编码按单键验收，不承诺任意触摸多键和弦；MIDI 负责外部多音输入。

ADS1115 · PMOD2

  • VDD → 3.3V，GND / ADDR → 公共 GND，I²C 7位地址 0x48。
  • SCL → D14，SDA ↔ E15；I²C 上拉保持 3.3V。
  • A0 / A1 保留压力0 / 压力1。
  • A2 / A3 保留音量滑杆 / 音高滑杆。

原 8 线矩阵 · PMOD1

  • R1 / R2 / R3 / R4 → T11 / M14 / T12 / J14。
  • C1 / C2 / C3 / C4 → P11 / R11 / M15 / J16。
  • S13 / S14 与 MIDI PC 共同修改同一当前音色；S15 / S16 菜单保持基线。
  • 保留现有矩阵作菜单 / 组合键，不按另一块排线的物理顺序盲换。

耳机 / HDMI / 调试

  • 板载 PT8211 → 原 3.5mm 耳机输出；已有音频与 HDMI 接法保持。
  • T13 = 调试 UART RX，M11 = 调试 UART TX，115200bps。
  • T8 = MIDI RX，31250bps。两种串口的波特率、数据含义和线路不能混接。
  • 不要把 TINY 的 3.5mm MIDI OUT 插入耳机口。

4　MIDI 映射合同与键盘设置

映射数据见 midi_tiny_mapping.json。这是本工程合同与建议设置，不是 MIDIPLUS 的出厂配置文件，也不会自动写入键盘。通道按用户界面 1~16 编号；线上状态字低四位对应 0~15。

输入V019 软件映射（到货后实测）配置 / 验收要点
CH1 Note On / Note Off主旋律默认监听通道1；Note On 的力度0等同 Note Off；非零 7bit 力度映射到合成器 8bit 力度。音符号按 MIDI 数值判断；本文 C4=60。不同软件八度名称可能不同。当前 MIDI 源码用 (v<<1) | (v>>6)，1→2、127→255，仍待最终仿真确认。
CC64 延音标准阈值 ≥64 开启，<64 关闭；延音影响 MIDI 来源的释放。先验证键盘实际发送 CC64。SUSTAIN 按键 / 脚踏的出厂模式不能仅凭灯推断。
CC7 音量控制主音量，与实体 A2 滑杆采用“最近发生变化的来源”仲裁。静止滑杆重复采样不能抢回；移动实体滑杆后应重新接管。可建议在 Control Center 把 K1 设为 CH1 / CC7。
Pitch Bend摇杆左右发送 Pitch Bend，14bit 中心8192；与 A3 音高滑杆采用最近变化来源仲裁。回中应恢复基准；具体弯音范围按最终实现验收，不在本文承诺半音数。手册编辑器称“CC128”是弯音选择项，线上并不存在 CC128 数据字节。
CC1 颤音控制颤音深度；约 6Hz 调制由 FPGA 生成。键盘只发送控制值，不提供 6Hz 时钟。摇杆上下建议设 CH1 / CC1，回中应停调制。
Program Change 0 / 1PC0 选长笛；PC1 选拨弦；与菜单 S13 / S14 同一音色状态。本工程自定义二音色映射，不是 GM 全音色表。若编辑器用1起始显示，须核对实际发出的0 / 1；不要猜旋钮默认发送 PC。
CH10 Pad Note 35/36 / 38/4035/36 → 底鼓，38/40 → 军鼓，保留力度。建议配置为36和38。在 MIDIPLUS Control Center 将 pads 设 NOTE 模式、通道10、所需 Note 编号并实际回读 / 抓消息核对；不假定到货配置已如此。
CC120 / Stop FC / System Reset FF全局紧急静音：清除 MIDI、矩阵 / 触摸、光弦及活动扫弦 / 延音状态，防止挂音。区别于正常松键；实际清音、队列取消与状态恢复应由集成测试确认。CC120只接受主旋律监听通道（默认CH1），接受后执行全局清音；FF和FC不受通道过滤。
Active Sensing FE只在收到 FE 后启用断流监控；启用后约 350ms 无 MIDI 数据流触发全局紧急静音。从未收到 FE 时，正常长按不因350ms无消息而超时。不要宣称 TINY 一定默认发送 FE。
CC123释放 MIDI 来源音符，走正常释放路径；不能误释放另一来源的同音。与 CC120 全局立即清音分开测试，验证延音 / 门控状态不遗留。
其他消息未支持的通道、其他 CC / PC / pads 音符、Aftertouch、SysEx / MMC、Clock / Start / Continue 等忽略其演奏动作；Stop FC执行全局清音。解析器须保持消息边界，不将数据误作音符；实时 FE / FF 仍按上两项处理。走带键默认 MMC 不承诺控制本工程菜单。

建议在电脑上先做一次可回退的键盘配置

  1. 按官方手册安装 / 打开 MIDIPLUS Control Center，用 USB 连接 TINY+，读取当前设置并保存备份。不同软件版本界面用词可能不同，按手册的 NOTE / CC / MIDI 通道字段识别。
  2. 主键盘发送通道设1；摇杆左右选 Pitch Bend，线上中心8192；上下选 CC1，相关发送通道也核对为1。
  3. 可把 K1 改为 CH1 / CC7；其余旋钮按需配置。厂家手册列 K1~K4 的默认 CC 为93/91/71/74，不能把旋钮转动却无效果直接判为 FPGA 故障。
  4. pads 设 NOTE 模式、通道10。明确挑两块设36和38并保存；35/36也可触发底鼓，38/40也可触发军鼓；其余Note当前不处理。手册示例 Bank A 含36/37/38/39，不能据此跳过配置核对。
  5. 用可查看原始 MIDI 事件的监视器核对 CH、Note、velocity、CC、Pitch Bend / PC。若 PC 无方便的实体发送方式，可由最终受支持的配置或测试端验证；不要假造一个不存在的 TINY 菜单。
  6. 保存到设备后断电重启并复查。电脑 USB 监视通过只证明 USB 路径；最后仍须测 TRS MIDI OUT → BMV → T8 这条实际链。
来源标签必须贯通：矩阵 / 触摸、本版 MIDI、光弦各自拥有音符来源标记；同一个 MIDI 音符号可以由多种来源同时持有。松开本地 C4 只释放本地 C4，MIDI C4 继续；反过来也一样。新扫弦只先释放旧扫弦来源，不能把仍按住的 MIDI 和弦一起关掉。MIDI、矩阵与光弦共享 32 声部，不是每种输入各32路。

5　双光束扫弦规则

  1. 把两套发射 / 接收端分别对齐成两束平行光路；沿手移动方向，A 与 B 相隔 3~5cm。3.3V 时发射到接收距离先取短于约20cm，避免一开始就在厂商标称边缘调试。
  2. 启动前移开手并对齐光路，保持两束无遮挡至少200ms。固件学习空闲电平；未规定遮挡必然高 / 低。若启动时手挡住，学习结果会错误，移开手后重新启动 / 复位。
  3. A 先、B 后：按音高由低到高扫；B 先、A 后：按音高由高到低扫。时差用于估计本次手势快慢，决定力度与逐音 2/4/6/10ms 间隔；这不是测得的整机声音延迟。
  4. 持有 MIDI 和弦时最多选6音扫弦；没有可用和弦时用 C4 E4 G4 C5 = 60/64/67/72。光弦固定拨弦音色，不跟随主旋律长笛切换。
  5. 只遮到一束或150ms内没有第二束：超时后回退触发一次扫弦，触发会更慢；不得把它描述成即时单光束响应。持续遮挡不重复发声，两束都恢复空闲后才重新等待下一次手势。
  6. 新手势触发扫弦前先释放上一组光弦，取消旧序列遗留音符，防止快速连续扫动挂音。两束同时变化没有可可靠判别的先后，不能作为方向测量结果。

来源隔离		矩阵 / 触摸先按 C4，同时 MIDI 按 C4；分别交换松开顺序。MIDI 和弦持续按住时连续触发两次扫弦。松一种来源不能释放另一种同音；新扫弦撤销旧光弦但 MIDI 和弦继续，无遗留门控。
07
光路基线		先测每条白 OUT：无遮挡 / 遮挡各记录电压；不要预设高低。A与B均对齐且无遮挡、手移开后复位，至少等待200ms。单独遮 A，再恢复；单独遮 B，再恢复。记录 A / B 各自空闲电压与遮挡电压、光程和环境。每一路应产生可区分电平，恢复后可再次触发。没有诊断界面时先用仪表观察，勿编造可点的光电状态页。
08
双束手势		两束沿手移动方向间距3~5cm。先无遮挡启动；做 A→B、B→A，分别快 / 中 / 慢移动。无和弦先听默认四音，再保持 MIDI 三音 / 超6音和弦扫动。分别升 / 降音序；快慢影响力度与间隔；无和弦60/64/67/72，持有和弦最多6音，始终拨弦。记录时差 / 实际逐音事件；不要仅凭听感证明2ms准确。
09
异常手势		遮单束并等待超过150ms；持续遮住不动；恢复两束再扫。故意在启动时挡住，观察学习错误后移手并复位恢复。单束只在超时后触发一次，长遮挡不重复；全空闲后重新可触发。启动误学可经正确无遮挡重启恢复。
10
清音 / 失联		先确认无 FE 时 MIDI 正常长按 >350ms 仍继续。再用已验证能生成原始消息的测试端先发送 FE、建立音符，然后停止数据流；另测 CC120、FF、CC123。用逻辑仿真替代不具备发送能力的实体键盘，不向调试UART灌MIDI字节。FE启用后断流约350ms全局静音；CC120 / FF 清所有来源与活动扫弦；CC123仅释放MIDI来源。TINY是否发FE、如何发测试消息均须记录，不能假定键盘有对应按钮。
11
32路验证		进入既有32声部验证流程，同时动 MIDI、矩阵 / 触摸、压力、滑杆与光束，再退出验证；实际入口按最终版本说明操作。验证期间真实输入不能污染验证音符、音量 / 弯音或事件序列；退出不回放积压事件，光束恢复空闲后才重新触发。保存最终仿真 / 实机结果。
