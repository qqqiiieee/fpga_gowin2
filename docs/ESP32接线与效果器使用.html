1. 先明确：接上线还需要什么

FPGA 负责发声和效果运算；ESP32 只提供 Wi-Fi 网页，把参数送给 FPGA 并显示实际回读。手机不传音频，也不替代 MIDI 接收器。需要分别给 FPGA 和 ESP32 部署匹配的固件。

FPGA 侧

Tang Primer 20K与原音频输出链路；四键仍使用A11/B11/N6/D11。V034新增长按1切音色，长按2切模式，短按保留页/播放/重播/选曲。

ESP32 侧

classic ESP32-WROOM32 开发板（ESP32 Dev Module），不是 C3/S3；数据 USB 线、适用的 USB 串口驱动、三根连接线。裸 WROOM 模块还需要下载/供电电路，不能等同于带 USB 的开发板。

首次给 ESP32 上传需要电脑和可传数据的 USB 线。之后演奏时可使用独立 USB 电源。你已有的 ESP32 开发板可用于此方案，另外准备数据 USB 线和三根杜邦线即可。

手机浏览器 ⇄ ESP32 Wi-Fi / UART2 ⇄ FPGA 参数控制 → 共用效果器 → 原音频输出
MIDI 键盘 MIDI OUT → 现有 MIDI 接收链路 → FPGA T8（31250 baud）
                        与手机 UART（115200 baud）是两条独立通道

2. 断电后按方向连接：GPIO17 → L9，N8 → GPIO16

ESP32 开发板FPGA / PMOD3方向与用途

GNDGND公共参考地，必须接

两端采用 3.3V TTL，115200 baud，8 数据位、无校验、1 停止位（8N1）。不能接 RS232 电平或 5V TTL。引脚名称按 FPGA 的方向读：RX 是 FPGA 收，所以接 ESP32 TX。L9/N8 是约束中的 FPGA 引脚名，不是随意数排针得到的位置；按底板 PMOD3 引脚对照定位。

FPGA 原 FTDI 调试串口 T13/M11、MIDI 接收 T8 均独立，不能拿来替代手机端口。本版已将协议文档和 ESP32 接线注释统一为 L9/N8。引脚以 multi_tone.cst 的 L9/N8 为准，ESP32 实际 GPIO 常量仍正确为 16/17。

3. 给 ESP32 准备并上传本版网页固件

本次已重编译更新过旋钮说明的 ESP 固件，见 build-result.json。上传步骤如下由你在确认硬件和端口后执行；本次代理没有执行上传或打开串口。

  1. 此前实机已确认V033（UserCode 0x000046D2）。V034新增混合模式2，需要匹配新版FPGA和ESP32；旧桥接程序只允许0/1，不能用旧网页验证HYBRID。新版当前是否已烧录，请查根目录 manifest.json 的烧录状态。
  2. 将 ESP32 开发板用数据 USB 线连电脑，在 Windows 设备管理器确认这块 ESP32 的 COM 号。不要选择 FPGA 的 FTDI COM 口。驱动缺失或只有充电线时先解决识别问题。
  3. 首次按本页命令上传前，先执行下面的编译准备命令；它也会建立上传所需的本地配置和草图目录。命令只编译，不上传，复用已安装工具链：
在仓库根目录进入 esp32_phone，再运行 build.ps1；构建与上传步骤见本目录上一级 esp32_phone/README.md。

仅 SDK/编译器复用原目录；V034 的草图、缓存、编译中间文件位于 .build_work，输出位于 build，不会覆盖旧版源码或构建产物。检查 build/build-result.json 中 compile_passed=true，并核对源文件及产物 SHA256。修改 esp32_phone.ino、bridge_core.h 或 web_ui.h 后必须重编译。

实际上传命令：把下面的 COMx 替换为已确认的 ESP32 端口。保留完整 build 目录（应用、bootloader、分区表等），不要只拿一个应用 bin 盲填烧录地址。upload 不会自动重新编译：

$espToolchain = '你的现有工具链目录'
& "$espToolchain\cli\arduino-cli.exe" upload `
  --config-file '.\.build_work\arduino-cli.yaml' `
  --fqbn 'esp32:esp32:esp32' --port 'COMx' `
  --input-dir '.\build' '.\.build_work\sketch\esp32_phone'

工具明确报告写入/校验成功后重启 ESP32；若停在连接阶段，核对端口、驱动、数据线，按开发板说明进入 BOOT 下载模式再试。编译成功不等于上传成功。上传完成后断电，接好第 2 节信号线，再给两端上电。FPGA 与 ESP32 各用自己的电源并共地。

4. 手机连接及第一次开效果

  1. 手机 Wi-Fi 选择 Tang20K-Music，密码 fpga2026。系统提示“无互联网”时选择保留连接，不要自动切走。
  2. 浏览器地址栏输入 http://192.168.4.1/。使用 HTTP，不是 HTTPS；本固件不保证自动弹出门户页面。
  3. 看到网页 ≠ FPGA 已连接。先等待状态变为绿色“FPGA 已连接 · 实际值持续回读”，完整回读结束且控件启用。这样才说明 ESP32 收到了 FPGA 有效应答；仍不等于声音、电气可靠性或延迟已验收。
  4. “演奏”区选择 KEY（直接按键演奏），主音量先设适中值，例如 120；音色可选“长笛 Flute”或“拨弦 Pluck”。确认实际 digital zero 为 0。
  5. “效果器”区把 FX 模式选为 Delay 延迟，等待确认；然后把湿度 Wet设为例如 80，等待“FPGA 已确认”和实际值一致，再弹键试听。
  6. 试 Chorus 或 Reverb 时先选择对应 FX 模式，再调湿度。换模式会恢复该效果自己的已存强度；不要假定上一种效果的湿度会自动覆盖另外两种。
  7. 比较干声时选 OFF，或把当前效果强度/湿度调到 0。听到的声音从 FPGA 原音频输出出来，手机网页本身没有录音、音频播放或音频传输。
如何判断一次修改完成：“请求已入队 / 等待 ACK”只代表接收了操作；需要收到 FPGA 正常 ACK，并且实际值达到目标，才显示确认。若显示“控制冲突，目标 X，实际 Y”，以实际值为准，检查滑杆、CC7、诊断/静音等控制来源。断链时控件禁用，恢复完整回读后重新操作；旧待发参数不会自动补发。

练习结束后保存与下次恢复

  1. 所有参数都确认生效后，在页面“JSON 参数预设”点击导出最近回读值，将 Tang20K-preset.json 保存到手机“下载”或“文件”。
  2. 下次上电，重新连接热点、打开网页，等绿色 FPGA 已连接后，点击导入 JSON 预设选择该文件，再等待各项确认。
  3. 目前导出的是音量、音色、当前效果及包络等参数，不包含演奏录音、乐谱或三种效果各自的全部历史强度。未导出的临时参数不能保证断电保留。
  4. 练习结束先松开琴键和延音踏板；若有持续音，用 Panic 清音，再断开电源。

Panic 清持续音并取消待发参数请求，不等同于一直静音，也不会替你撤销 FTDI 等其它来源的 digital zero。无声音先看实际主音量、输入模式与静音，不要仅观察 Wi-Fi 图标。

5. 四旋钮：三种互斥效果强度＋总音量

实体旋钮 / CH1 CC本版功能屏幕值
K1 / CC93接受到强度变化 → 选 Delay，并调其强度DL：已存 Delay 强度
K2 / CC91接受到强度变化 → 选 Chorus，并调其强度CH：已存 Chorus 强度
K3 / CC71接受到强度变化 → 选 Reverb，并调其强度RV：已存 Reverb 强度
K4 / CC74总音量，经现有仲裁器发单拍变化请求VL：最终实际主音量

三种效果共用一个效果器和历史 RAM，一次只有一种效果，没有新增三个并联 DSP 或 RAM。复位为 OFF，三个强度各保存 64；时间/反馈/调制默认 96/80/48。强度 0 表示当前效果只输出干声，模式可以仍显示 Delay/Chorus/Reverb。在手机上选择 OFF 可明确关闭效果。

旋钮转了没变：先经过目标，再继续转

例如 DL 显示 64：慢慢把 K1 转到这个值附近，或从目标一侧跨到另一侧。首次接受相同值只完成接管，不切模式；再继续转动造成实际变化，才选择 Delay。未接管的远处值不会让参数突然跳变。已接管的非活动效果仍记住自己的目标，稍微改变它的强度即可切回；重复发送它的旧值不会抢模式。

CC 原始值为 0–127，扩展规则为 (v<<1)|(v>>6)，覆盖端点 0/255，但并非能逐一输出全部 256 个整数。因此软接管允许相差 1 码；手机能写全部 0–255。屏幕显示保存目标/实际音量，不显示尚未接管的旋钮物理位置。

手机和旋钮同时用

  • 手机参数 3 选择模式：恢复对应已存强度，并清除三个效果旋钮的接管历史。手机选 OFF 后，重复未变的旋钮值不会自动开启；经过目标再改变才会开启对应效果。
  • 手机参数 4 改湿度：同步当前效果的保存值，并重新要求该旋钮软接管。OFF 时更新最近选择的效果，复位默认归 Delay。手机 SET3/SET4 同拍优先，冲突的效果 CC 整条丢弃，不留旧采样来伪造跨越。
  • K4 按实际主音量接管；CC7 改变最终音量后，K4 必须重新接管。自己的正常请求回读不会使它每转一步就失去接管。
  • 手机参数 0 与 K4 同拍时手机优先。手机显式 SET 允许请求重取所有权；K4 重复值不发请求。V034 已停用实体滑杆，A2/A3 不再参与音量或弯音。CC7 保留原仲裁器“与共享上次请求值比较”的规则。
  • 四个菜单键仍负责原菜单/跟弹操作，不新增 FX 快捷键；top 的 ui_fx_cycle 固定为 0。键盘单独选效果使用 K1/K2/K3，全部模式也可由手机选择。

6. Pad、黑白键和音色分别是什么

Pad 非零力度的 Note On 触发对应打击乐，不作为钢琴旋律声部分配；力度 0 不敲击。旋律和四旋钮默认通道 1。以上是当前 FPGA 接收规则，不代表已经读到这把键盘的实际 Pad/CC 配置；需要实物联调确认。手机不会替你重配键盘 Pad。

黑键和白键的半音音高原本就已实现。当前音频使用完整 MIDI 音符，不将黑键压成白键；黑/白不是两种独立音色。可选音色是长笛和拨弦。V034 图形默认显示 MIDI41(F2)–72(C5) 的 32 个连续半音，显示窗口已按用户确认的左端 F2 校正；窗口外音符不因此变成错误音高。显示几何/标签由主流程单独验证，本审计不把 HDMI 桩仿真当实屏测试。
