Tang Primer 20K · V017基线 · V018阶段1

GVS触摸键盘接线与标定

SPI / ADS / 备用矩阵接法已明确模块供电与逐键数值仍待实机验证

新输入通路为 GVS模拟S → 两只10k分压 → MCP3208 CH0 → FPGA。ADS1115的两路压力、两路滑杆和板载3.5mm耳机输出继续使用。现有8线矩阵可作为菜单、组合键的备用输入，保留现有件即可，无需另买膜键盘。

接线的三条关键点：模拟S不能直接接FPGA；触摸板、MCP3208、ADS1115与FPGA使用3.3V逻辑并共地；MCP模块的5V–18V端子不接。商品图/原理图含3V3输入，用户已确认下述供电接法，动手前按实物丝印核对；这不等于已经通电实测。

1　按这张图接线

模块端口接往哪里核对事项
GVS V / GPMOD0 3.3V / GND按实物V、G、S丝印确认方向。
GVS S10k串联 → 分压节点 → MCP CH0节点再经另一只10k到GND；两只电阻按需补齐。不得把S接到FPGA数字引脚。
MCP 3V3 / GPMOD0 3.3V / GND3V3是模块输入端口名；5V–18V端子悬空。按用户已确认接法，未宣称实测供电成功。
MCP CLKPMOD0 SCLK = T6时钟从FPGA送到模块。
MCP DINPMOD0 MOSI = P6数据从FPGA送入模块。
MCP OUTPMOD0 MISO = R8数据从模块送回FPGA；不要与DIN接反。
MCP CSPMOD0 CSn = T7低有效片选。

两只10k构成理想2:1外部分压，V节点 = S × 10k/(10k+10k) = S/2。若S达到3.3V，理想节点约1.65V，低于模块2.5V参考；这是电路计算值。CH0板载分压、输入负载未知，可能使码值在此基础上进一步缩小，不能直接照抄商家电压表。

2　先做断电检查，再观察原始码

  1. 先断电。核对PMOD0的3.3V、GND及T6/P6/R8/T7对应排针位置，不能从本示意图猜针序。
  2. 按实物丝印接V、G、S及模块3V3、G、CLK、DIN、OUT、CS。确认5V–18V端子未接；用通断档确认各模块共地、供电未短路。
  3. 确认S先经过串联10k，CH0接在两电阻中点，另一个10k从中点到地。首次上电可用万用表核对供电及CH0对地电压，测量结果自行记录；节点不应超过2.5V参考。不能把理想1.65V计算值当实测记录。
  4. 使用主agent集成并明确启用触摸诊断的固件。remote_debug_link.DIAG_ENABLE默认0；旧V017或未启用诊断时，工具会超时，不会替你改固件或烧录。
  5. 结束其它占用该串口的程序及远程输入会话，等待原固件的remote超时回退。新诊断查询不会退出、开启或续期remote模式。

在PowerShell进入工程。串口固定115200、8N1；COM8只是当前device_config.json的值，可以用--port指定其它端口。工具不修改配置文件。

Set-Location 'D:\Gowin_project\instrument_touch_20261024'
python tools/touch_calibrate.py --list
python tools/touch_calibrate.py monitor --port COM8 --count 30
# 不带子命令时默认持续monitor；Ctrl+C结束
python tools/touch_calibrate.py

串口打开、枚举依赖pyserial，优先使用项目已有含pyserial的Python；工具也识别工程根目录或tools下的runtimepyserial/serial。确实缺依赖时，安装到你准备使用的Python：

python -m pip install pyserial

monitor只发送flags=0x80，显示raw、touch_keys、主键位keys及诊断字段。先全松，期望原始码raw<4；再一次只按一个位置并观察码值有无稳定变化。未标定时键位可能错误，先看raw；原始码固定在有效档位时不能仅凭数值区分真实长按与模拟故障。

3　逐键采集：先全松，再按住

按实际4×4位置采集，不按模拟码值大小排序。逻辑行序如下；商家参考表中的B/C重印或顺序差异靠实际位置采集修正。

1index 02index 13index 2Aindex 3
4index 45index 56index 6Bindex 7
7index 88index 99index 10Cindex 11
*index 120index 13#index 14Dindex 15
# 输出目录必须是新的；命令完成前不会创建标定输出
python tools/touch_calibrate.py calibrate --port COM8 --output-dir 'D:\Gowin_project\触摸实测_首次'
  1. 每个位置先提示“松开全部触摸键”。手完全离开，等稳定后按Enter；工具等待默认0.25秒，再查询默认24次记录松开基线。
  2. 按住提示的实际位置，用另一只手按Enter，并持续按住直到提示已采集。查询间隔默认0.03秒，不含串口事务耗时；采集过程不发写中心命令。
  3. 重复全部16项。遗漏、错误位置、噪声过大、原始码近零/饱和或中心过近都会拒绝，失败后排障并重新完整采集。
  4. 全部通过后，保存touch_calibration.json和touch_centers.hex。没有--apply时只保存；JSON的apply.status=not_requested表示尚未向硬件写入。
检查规则与意义
全松采样原始码均<4；不能以未校准的键位掩码代替基线采集。
有效中心中位数必须为8..4094，采样窗口不能落到空闲区或出现4095饱和码。
档位间隔任意两中心距离≥12；恰好12可接受，<12拒绝。未知内部分压导致过分衰减时停止，不能强行合并键位。
动态窗口每键取最近中心距离gap，t=max(2,min(32,gap//4))。host要求采样峰峰跨度<t/2，且≤默认全局上限8码；明显小于相邻档gap/4。
位置顺序输出始终为rowmajor16项，不因电压大小、B/C参考表顺序改变数组顺序。

可通过--samples、--settle、--interval调整手动采样节奏；--max-noise可设得更严格，--min-separation不能低于12。增大噪声上限仍不能绕过动态窗口检查。完整选项见calibrate --help。

工程默认assets/touch_calibration.json来自商家参考值换算，标记为estimated_not_measured，不是逐键实测。外加2:1与未知板载分压叠加后，实际中心可能再缩半。运行时标定记录实际CH0码值，可修正额外分压与实际B/C位置差异；量程过分衰减、噪声或前端故障仍会拒绝。

4　显式应用运行时表

# 换用一个新目录；16项全部合格后，才会进入写入阶段
python tools/touch_calibrate.py calibrate --port COM8 --output-dir 'D:\Gowin_project\触摸实测_运行时' --apply

完成16项采集、保存后，工具再次提示全松。按Enter后在整个写入阶段保持手离开触摸板。每次写之前查询至少3次，要求raw仍在松开基线附近且touch_keys=0；再发送一个0x81请求，核对版本09、序号、XOR，以及ACK的准确索引、中心值和0xA100|index标记。默认不自动重试不确定的写入。

收到16个匹配写ACK后，工具另发0x80查询并检查全松状态，才将JSON记为apply.status=confirmed、writes_confirmed=16、query_confirmed=true。查询只能确认诊断链路及当前状态，协议没有一次读回完整16中心表的命令。

写入中断、错误ACK或超时会停止并记录unconfirmed及已确认项数。即使最后一项ACK丢失，硬件也可能已接收它，因此运行时表可能部分更新；不能当作成功或自动回滚。保持全松、排障后重新完整标定并应用。只采集失败时不会开始写中心。

运行时表位于FPGA RAM；复位恢复工程HEX，掉电不会靠这次串口操作持久化。工具不烧录、不复制文件进src、不修改device_config。

5　需要持久化时：由实测JSON重新生成，再构建

以下是采集完成、人工确认位置正确后主动更新工程默认值的步骤。先另存旧JSON和HEX。保存的实测JSON包含生成脚本要求的row_major_keys与centers；工具输出HEX为16个12位词，每行三位小写十六进制、无头部、无地址，与生成脚本重建结果逐字节相同。

6　串口09诊断约定

请求与回复都为16 bytes，小端16位字段。校验为XOR(bytes[2]..bytes[14])。09是诊断协议版本；原08普通ACK布局、普通远程请求维持原约定。

请求字节位置（从0开始）内容
0..3A5 5A seq flags
4 / 5 / 6keysLo / keysHi / velocity
7..14adc0Lo adc0Hi adc1Lo adc1Hi adc2Lo adc2Hi adc3Lo adc3Hi
15XOR
  • flags=0x80：只查询，payload全部为0；不接管或续期remote模式。
  • flags=0x81：写一个中心；byte4低4位为rowmajor index=0..15，高4位必须0；byte7/8为8..4094中心，其余payload为0。值<8、>4094或非法索引会被固件静默拒绝；host预先拒绝这些值。写请求同样不修改或续期remote模式。
回复字节位置内容 / 含义
0..45A A5 09 seq status
5..6主键位keys，16 bit小端
7..8 / diag0touch_raw，12 bit
9..10 / diag1touch_keys，16 bit
11..12 / diag2查询：状态/debug；写ACK：(cal_index<<12)|cal_value
13..14 / diag3查询：采样序号/debug；写ACK：0xA100|cal_index
15XOR

host不把查询diag2当写入回执，也不把diag3未定义的debug位当物理时延测量。串流允许噪声前缀、帧碎片，坏XOR、错误版本和错误seq不会作为成功回复；等待到超时后明确失败。普通08ACK不能替代09诊断。

7　实机验收与排障

现象 / 项目检查与合格依据
没有09回复核对--list、--port、串口占用、固件版本与DIAG_ENABLE；115200 8N1。工具不自动烧录；仅08 ACK表示不能证明诊断已启用。
raw总为0或4095断电后检查V/G/S丝印、3V3供电、共地、两电阻节点、CH0、DIN/OUT及CS球号。不要用假设的默认中心掩盖接线问题。
全松raw≥4先完全松开，检查CH0偏置、负载及接线。host不会将该状态当合格空闲。
中心缩小、相邻键混淆未知板载分压可能再次衰减。逐实际位置重采；gap<12或波动超动态窗口必须拒绝并查模拟前端。
B/C或其它键错位以图中实际行列重新完整标定。不要只按商家电压表重排，或在半张表上继续试奏。
单键动作应用后逐键按下、松开，检查touch_keys按对应bit变化、全松回0、没有游离键，并记录实际音符。GVS正常单键使用，不承诺多键和弦；后续MIDI承担和弦。
保留功能分别测试压力A0/A1、音量A2、音高A3、现有矩阵菜单/组合键及板载3.5mm耳机输出。既有接法无需迁移。
采样与延迟集成目标为MCP SPI 500kHz、原始采样5kHz、触摸stable=3；矩阵1ms帧、DB=3。这些是数字侧配置，触摸芯片内部响应未知，不能据此宣称实机端到端延迟≤5ms。

把实机记录分开填写：供电实测电压、16中心及噪声范围、每键按/松现象、压力/滑杆/矩阵、耳机声音。host的串口回执验证与离线单元测试，都不能代替这份硬件记录。
